<critical_facts>
These are VERIFIED against the pinned wheels on this machine
(`astronomer-cosmos==1.15.0` in the uv cache, `dbt-core==1.12.2` in
`.venv-dbt-warehouse`). They are not documentation claims. Full citations are in
`03-RESEARCH.md` §DCF-1, §DCF-2, §Q1, §Q2.

1. **`DbtSourceLocalOperator` is NOT re-exported from `cosmos.operators`.**
   `cosmos/operators/__init__.py` re-exports twelve operators and the Source
   operator is not one of them. The class lives at
   `cosmos/operators/local.py:1181`. Extending the existing
   `from cosmos.operators import DbtDocsOperator` line raises `ImportError` and
   takes the entire DagBag down. The import must be a **new, separate line**:
   `from cosmos.operators.local import DbtSourceLocalOperator`.

2. **dbt runs in-process, not as a subprocess.** `airflow.requirements.in` pins
   `dbt-core` into the Airflow image's own Python, so Cosmos'
   `_discover_invocation_mode()` selects `InvocationMode.DBT_RUNNER` and
   `dbt_executable_path` is discarded (`cosmos/dbt/runner.py:93`). Passing
   `dbt_executable_path=DBT_EXECUTABLE` is still correct for consistency with
   the existing `DbtDocsOperator`, but it is not what makes dbt run. Code
   comments and W1 must therefore say the gate is on the **dbt result status**
   (exit code 1 on the CLI, `dbtRunnerResult.success is False` under the
   in-process runner) — both derive from the same
   `FreshnessTask.interpret_results` computation, so the CI proof and the
   Airflow runtime do not diverge.

3. **The operator fails closed by default.** `run_command` calls
   `handle_exception(result)` unconditionally; under `DBT_RUNNER` that raises
   `CosmosDbtRunError` when `result.success` is false. `on_warning_callback` is
   only a warn-level hook and gates nothing — do not pass it.

4. **The fail-closed chain needs no modification.** freshness failure →
   `dbt_warehouse.dbt_producer_watcher` becomes `upstream_failed` →
   `validate_dbt_artifacts` raises, because `upstream_failed` is already in its
   `terminal_failures` set at `dags/warehouse_dbt.py:349` →
   `publish_mart_assets` (trigger rule `ALL_DONE`) re-reads the validation state
   and raises at `:396-400` before `_audit_and_counts` is ever called. No new
   guard anywhere.

5. **`core.*` needs no negative declaration.** `FreshnessSelector.node_is_match`
   ends in `return node.has_freshness`, and `SourceConfig.freshness` defaults to
   an empty (falsy) `FreshnessThreshold`. Sources without thresholds are simply
   not selected — silently, with no error. Do **not** add `freshness: {}` to
   `core.*` "for symmetry".

6. **An empty staging table produces an ERROR, not a pass.**
   `BaseAdapter._create_freshness_response` maps a NULL `max(loaded_at)` to
   `datetime(1,1,1)`, i.e. an age of ~2025 years. Fail-closed and desirable, but
   it means freshness must never run before the load or the CI seed.

7. **`config:`-level placement is the current, non-deprecated form** in
   dbt-core 1.12.2 (`dbt/parser/sources.py:426`). Top-level `loaded_at_field:`
   is deprecated. Use `config:`.
</critical_facts>
