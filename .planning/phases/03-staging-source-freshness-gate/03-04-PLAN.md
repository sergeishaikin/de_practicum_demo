<critical_facts>
1. **A1 is UNRESOLVED and must be observed, not guessed.**
   `_add_watcher_dependencies` links the Cosmos producer to the consumer sensors
   only when `"DbtDag" in dag.__class__.__name__` (`cosmos/airflow/graph.py:896-899`).
   `warehouse_marts_validation` is a plain `@dag`, so that branch is skipped and
   the consumer sensors have no in-group upstream — meaning they are probably
   roots too, and `check_source_freshness >> dbt_group` probably becomes upstream
   of the producer **and** every consumer sensor. Probably. Run
   `scripts/dump_dag_structure.py` and read the real mapping before writing a
   single assertion. (`03-RESEARCH.md` §Q3, Pitfall 8, Assumptions Log A1.)

2. **`scripts/dump_dag_structure.py` emits, per DAG,
   `"tasks": {task_id: sorted(direct upstream task_ids)}`** (`:57-60`), and
   `tests/test_dags.py`'s module-scoped fixture pipes it into
   `docker exec -i de-demo-airflow python -` and parses the last JSON line
   (`:47-61`). No Airflow import happens on the host.

3. **The marts DAG assertions use the subset (`<=`) + per-edge style
   deliberately** (`tests/test_dags.py:204-214`) because Cosmos generates a
   variable number of consumer tasks. A new top-level task changes no existing
   assertion, provided it declares no inlets or outlets — `:215-219` filters
   `task_assets` down to `publish_mart_assets` only.

4. **`validate_dbt_artifacts` is reachable as a real callable.**
   `bag.dags["warehouse_marts_validation"].task_dict["validate_dbt_artifacts"].python_callable`
   yields the undecorated function, the same way `publish_mart_assets` is
   accessed at `test_airflow_workflow_behavior.py:187`. Its `terminal_failures`
   set at `dags/warehouse_dbt.py:349` already contains `"upstream_failed"`, so it
   raises on the **first** poll iteration and never reaches `time.sleep(5)`.
   `time.sleep` therefore does not need patching — but the assertion must prove
   the raise happened rather than a timeout, and `run_actual_callable` has a
   120-second `docker exec` timeout as the backstop.

5. **The DagBag loads `dags/warehouse_dbt.py` as its own module object,** so a
   callable's `__globals__` are NOT the separately imported `warehouse_dbt`
   module — there is a load-bearing comment saying exactly this at
   `test_airflow_workflow_behavior.py:188-190`. The new branch must patch
   `validator.__globals__`, not `warehouse_dbt.__dict__`.

6. **Nothing existing becomes time-dependent.** No current fixture touches
   `loaded_at`, and `replay_truncate_precedes_load` patches `_copy_csv` entirely,
   so the new column cannot affect it.
</critical_facts>
