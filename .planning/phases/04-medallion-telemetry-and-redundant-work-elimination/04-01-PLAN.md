(1) On `FakeMetrics`, add `phase(self, name: str) -> dict` and `cycle(self) -> dict`.

`AssertionError` naming every captured `(phase, status)` pair when there is not exactly
one match. `cycle()` is `phase("cycle")`. Uniqueness must be asserted, not assumed —
the whole reason these exist is that `records[-1]` becomes ambiguous once one logical
run emits several records. Do not change `record()` or `records`; existing
`records[-1]` call sites must keep working.

(2) Add a module-level `scripted_monotonic(values)` returning a zero-argument callable
that yields each value in turn and raises `AssertionError` with the exhausted sequence
when called more times than there are values. It is intended for
`monkeypatch.setattr(m.time, "monotonic", scripted_monotonic([...]))`-style use so
duration assertions are exact integers rather than timing luck.

Extend the module docstring to say these two helpers serve the metric-identity
contract. Do not add a pytest fixture, plugin, conftest hook, or any new module —
`AGENTS.md` forbids adding a verification layer the change does not require.
  </action>

The local `FakeTable` in `tests/test_m4_gold.py` has no `current_snapshot()` and discards
`snapshot_properties`, so it cannot express Gold provenance at all. Extend it in place
rather than switching to `tests/support/fakes.py:FakeTable`: the shared double's
`scan()` returns `FakeScan(self.df)` and yields `None` for an empty table, whereas this
module's double returns an empty typed Arrow table, and several Gold tests depend on
that. Record that reason in a comment on the class so the duplication is a decision, not
an oversight.

Add to the local `FakeTable`: a `snapshots` list, an `add_snapshot(**summary)` method
that appends a `SimpleNamespace(snapshot_id=<1-based position>,
summary=SimpleNamespace(additional_properties=dict(summary)))` and returns it, a
`current_snapshot()` returning the last snapshot or `None`, a `snapshot_properties` list
capturing the `snapshot_properties` kwarg of every `overwrite`, and an `overwrite` that
appends a snapshot carrying those properties. Mirror `tests/support/fakes.py:FakeTable`
field-for-field so the two doubles stay recognisably the same shape.

Separately, change the `run_b2` stub in `setup_gold_run` from `lambda *args: None` to
`lambda *args, **kwargs: None`. This is required and is a correction to
`04-RESEARCH.md` §5c, which states that `lambda *args: None` absorbs an added
keyword-only argument. It does not: a bare `*args` lambda raises `TypeError` on any
keyword argument, and plan 04-03 will call `run_b2(..., cycle_id=...)`. Leave the
`ensure_table` stub alone — its signature is not changing.

Add one test in this module proving the double itself behaves: an overwrite records its
snapshot properties and moves `current_snapshot()`, and a table seeded with a
property-bearing snapshot followed by a bare one reports the bare one as current. That
second case is the fixture plan 04-05 needs for the "read provenance from
`current_snapshot()` only" rule.
  </action>
