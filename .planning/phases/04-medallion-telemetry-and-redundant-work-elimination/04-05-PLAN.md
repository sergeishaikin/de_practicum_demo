<objective>
Stop rewriting Gold when persisted Silver has not moved, using the same snapshot-property
idiom the repository already relies on, and amend the ratified ADR that says otherwise.

Purpose: the measured baseline shows Gold costing 4.1–5.6 s on **every** cycle including
the four of five cycles that did no work at all. GLD-01 removes that. It is memoization,
not incrementalisation: Gold stays a full, exactly-verifiable rebuild whenever it runs.

Output: `source-silver-snapshot-id` stamped on the Gold commit, a current-snapshot-only
provenance read, a fail-safe skip decision, `gold_skipped` / `gold_snapshot_id` on the
metric rows, `gold=skipped` reachable in the cycle marker, and a narrow superseding
amendment to ADR-0001 D-4.

**Scope decision the executor must not widen — read this before writing code.** The skip
applies **only when Gold is served from persisted Silver** (`GOLD_SOURCE =
persisted_silver`, the live runtime `b2/persisted_silver/1`). Under `GOLD_SOURCE =
legacy` the Gold input is the in-memory legacy rebuild derived from Bronze, not persisted
Silver, so a persisted-Silver provenance stamp would not describe it. This is faithful to
the locked wording, which speaks of persisted Silver throughout, and to ADR-0001 D-4,
whose sentence is about the persisted-Silver rebuild. A Bronze-provenance skip for the
legacy Gold source is **not** part of GLD-01 and must not be invented here.

**Hard constraints.** Gold does not become incremental, partial or delta-based. The B2
algorithm, shadow comparison semantics, FF-14 rules and `RUNTIME_ROLLOUT_MATRIX` are
untouched.
</objective>

  <action>
Add `GOLD_SOURCE_SILVER_SNAPSHOT_KEY = "source-silver-snapshot-id"` next to the existing
`SILVER_WORK_ID_KEY`.

Add `_gold_provenance(gold) -> int | None` reading
`gold.current_snapshot()` and returning `int(...)` of
`snapshot.summary.additional_properties.get(GOLD_SOURCE_SILVER_SNAPSHOT_KEY)`, returning
`None` for an absent current snapshot, an absent property, or a value that does not
parse. Do **not** walk `metadata.snapshots`. Reading only the current snapshot is what
makes a Trino maintenance rewrite of Gold (`dags/lakehouse_maintenance.py` lists
`("gold", "orders_daily_metrics")` in `MAINTENANCE_TABLES`) invalidate provenance
automatically: after maintenance, provenance reads as absent and the medallion rebuilds
Gold once. Walking history would be fail-open, because an expired or superseded snapshot
could vouch for a Gold state maintenance has since replaced. State that reasoning in the
function docstring — it is the security-relevant property of this change.

Change `_write_gold` to `_write_gold(catalog, gold_df, *, source_silver_snapshot_id:
int | None) -> tuple[bool, int | None]`, returning `(written, gold_snapshot_id)`. It
ensures the table and loads it as today, then:

- if `source_silver_snapshot_id` is not `None` and equals `_gold_provenance(gold)`,
  perform no write and return `(False, <current gold snapshot id>)`;
- otherwise `overwrite` the frame, passing
  `snapshot_properties={GOLD_SOURCE_SILVER_SNAPSHOT_KEY: str(source_silver_snapshot_id)}`
  **only** when `source_silver_snapshot_id` is not `None`, and return
  `(True, <new gold snapshot id>)`.

Putting the decision inside `_write_gold` keyed on a nullable argument means there is one
code path and no mode branching inside it: callers that have no persisted-Silver basis
pass `None` and therefore always write and never stamp. `_run_legacy` passes `None`.
`_run_m4` passes the persisted-Silver snapshot id when `GOLD_SOURCE ==
"persisted_silver"` and `None` when it is `legacy`.

Two traps to respect explicitly, both verified in research:

- a full `overwrite` produces up to **two** snapshots (a DELETE then an APPEND), both
  carrying the same properties, and the DELETE half is elided when nothing matches — so
  no test may assume a fixed Gold snapshot stride;
- the APPEND half is **not** elided for an empty frame, so a "stamp-only empty
  overwrite" writes a snapshot anyway. Never refresh provenance that way; it would defeat
  the skip and grow snapshot history.

Wire the outcome through: the `gold` and `cycle` records gain `gold_skipped=not written`
and `gold_snapshot_id`, and the cycle marker's `gold` field becomes `skipped` when
`written` is false. Do not introduce a new `status` value for a skipped Gold — the
exporter's `SOURCE_UP` set and the `LakehouseApplicationFailure` alert both key on
`status` and would break.

Keep the `gold` phase record even when the write is skipped: its `duration_ms` then
measures the decision, which is exactly the number that shows the saving.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Iceberg Gold snapshot summary → medallion skip decision | A property value read from the catalog decides whether a correctness-relevant rebuild happens |
| Trino maintenance procedures → Gold table | An external writer can replace Gold data files without knowing about the provenance property |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-16 | Tampering | stale provenance vouching for a superseded Gold state | mitigate | `_gold_provenance` reads `current_snapshot()` only; a Trino `optimize` / `expire_snapshots` rewrite produces a current snapshot without the property, so provenance reads as absent and Gold is rebuilt once |
| T-04-17 | Elevation of privilege | a skipped rebuild presenting as a completed one | mitigate | `gold_skipped` is recorded on the `gold` and `cycle` rows and in the stdout marker, so a skip is always visible in the evidence rather than indistinguishable from a write |
| T-04-18 | Spoofing | `None == None` certifying an empty lake | mitigate | A `None` `source_silver_snapshot_id` never matches; `_write_gold` writes and stamps nothing. Covered by an explicit unit test |
| T-04-19 | Input validation | unparsable snapshot-property value | mitigate | Snapshot-property values are strings; `_gold_provenance` parses defensively and treats a non-numeric value as no provenance, following `list_bronze_work` and `load_completion_ledger`'s reject-before-trust style |
| T-04-20 | Repudiation | a ratified ADR contradicting the code | mitigate | D-4 is amended as a superseding, evidence-citing amendment, not a silent edit; the six reasons stay verbatim so the original decision remains auditable |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No package is installed in this plan |
</threat_model>
