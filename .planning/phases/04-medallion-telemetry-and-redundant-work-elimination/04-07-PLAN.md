Rewrite each claim so it matches the shipped behaviour. Read the code as landed rather

**The row-count claim.** Every "one row per writer batch / medallion cycle" statement is
now wrong for the medallion. Replace it with the truth: the writer still writes one row
per batch; a medallion cycle writes one `cycle` row plus the phase rows for the phases it
executed, all sharing a `cycle_id`, with the `cycle` row written last. Name the closed
phase set. Say that the `cycle` row is the envelope and that phase durations are
mutually non-overlapping, and state the one honest wart: the incremental writer's own
state-load preamble is attributed to no phase, so the phase durations sum to at most the
cycle duration rather than exactly to it.

**The sample queries.** `README.md`'s and `docs/TESTING.md`'s `group by source, status`
examples now double-count. Replace them with queries that filter `where phase = 'cycle'
or phase is null`, and add a one-line note saying why that predicate is there.

**The new columns.** Extend `README.md`'s column table with `cycle_id`, `phase`, the
three snapshot ids, `shadow_skipped` and `gold_skipped`, describing what each means.

**The interpretation rule (MTL-02).** Add the status-qualified table for rows with
`cycle_id IS NULL`, exactly as locked in `04-CONTEXT.md`: `success` with
`gold_duration_ms > 0` is an outer cycle; `success` with `0` is a nested B2 phase;
`shadow_failed` is an **outer cycle** that aborted before Gold; `failed` is a nested
phase for which **no outer record exists**. Say explicitly that the naive
`gold_duration_ms = 0` rule misclassifies `shadow_failed`, the safety-critical row.
Point at `classify_metric_row` in `iceberg/common/ops.py` as the executable form, so the
prose and the code cannot drift apart silently.

**The honesty statement (MTL-02b).** State that the `shadow_failed` and `failed` branches
were **derived by reading the emission sites in the medallion, not observed in recorded
data**: every one of the ten rows in `artifacts/b2-rollout/06-o1-window.json` has
`status: success`. Also record the compressed caveat — a `failed` row can come from the
incremental writer or from an aborted legacy cycle under `QUALITY_FAIL_ON_VIOLATIONS=1`,
and the two origins were not distinguished; what they share is that no outer record
exists for that cycle.

**The Prometheus contract.** In `docs/observability/O1-runtime-observability.md`, record
as a deliberate contract that **only the `cycle` phase reaches the Prometheus
collectors** and that per-phase granularity lives in PostgreSQL only. Say why: labelling
gauges by `source` alone meant the outer record reset the nested record's gauges to zero,
which weakened `LakehouseUnresolvedWork`. Confirm the metric contract list and every
label set are unchanged, so no Grafana target or alert rule needed rewriting. Add the
Gold-provenance and shadow-certificate signals to the ownership table.

**The skip behaviour.** In `README.md` and `docs/ARCHITECTURE.md`, document that Gold is
rebuilt in full whenever persisted Silver moves and skipped when the current Gold
snapshot's `source-silver-snapshot-id` already names the current persisted Silver
snapshot; and that the shadow comparison is skipped when a durable certificate covers the
current Bronze, the current Silver, the runtime and the projection contract. State that
every failure to establish those facts results in doing the full work, and that a Trino
maintenance rewrite of Gold deliberately costs one extra rebuild. Cross-reference the
ADR-0001 D-4 amendment.

**The growth number.** Restate row growth honestly: at a 60 s interval the medallion now
writes roughly two to four rows per cycle instead of two, so the recorded ~970 rows/day
grows accordingly. Say that retention was not decided in this phase.

Keep every edit minimal and in each document's existing voice. Do not restructure a
document, do not add a new documentation file, and do not delete a section.
