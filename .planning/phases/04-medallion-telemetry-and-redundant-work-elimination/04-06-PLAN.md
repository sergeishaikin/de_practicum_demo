<objective>
Stop performing a full Bronze scan, a full legacy Silver rebuild and a full business-state
comparison on every cycle when nothing that the comparison depends on has moved.

Purpose: at the measured baseline this is the dominant cost — 21–45 s of the 26–50 s
cycle — and four of the five recorded cycles did no work at all. A receipt-gated fast
path removes it without weakening the gate, because the receipt's identity covers
everything the comparison's conclusion depends on.

Output: a durable shadow certification receipt, identity helpers for the runtime and the
projection contract, the fast-path decision, `shadow_skipped` on the metric rows,
`shadow=skipped` reachable in the cycle marker, and one integration scenario proving the
receipt survives a process restart.

**Locked constraints carried in.** Do not skip on Bronze identity alone — Silver moves
independently through B2 recovery. The receipt must carry at least
`bronze_snapshot_id`, `silver_snapshot_id`, runtime/cutover configuration identity,
projection/business-contract version, the comparison result and a comparison timestamp.
Skip only when **all** hold: current Bronze equals certified Bronze, current Silver
equals certified Silver, the runtime and projection contract are unchanged, and the
previous comparison succeeded. When a comparison does run, the existing
`_pin_bronze_boundary` behaviour is preserved so both candidates describe the same
logical source.

**Storage decision, and why it deviates from the research recommendation.**
`04-RESEARCH.md` §3d recommends a PostgreSQL receipt table. This plan puts the receipt in
MinIO instead, as a single JSON object alongside the medallion's existing
`progress.json` and completion ledger. Three reasons, all verifiable:

1. SHD-01h requires proving the receipt survives a process restart, and the only place
   that is proved is `ci-m5-gates.yml`, which starts **only** `minio` and `iceberg-rest`
   and runs the medallion with `METRICS_ENABLED=0`. A PostgreSQL receipt would make the
   fast path unreachable in every integration proof this repository has.
2. `Metrics.record` swallows every exception by design so observability can never break
   ingestion. The receipt read must do the opposite and fail toward doing the work.
   Keeping the certificate out of the observability object keeps those two behaviours in
   separate homes rather than one object with two contradictory contracts.
3. The medallion already owns durable MinIO state, and `tests/support/b2_fakes.py:FakeFS`
   already models the exact `S3FileSystem` slice it uses, so unit coverage is free.

The cost, stated plainly: an operator cannot query the certificate with SQL. That is
mitigated because the *decision* — `shadow_skipped`, `shadow_comparisons` — is recorded
on the metric rows in PostgreSQL, which is where operators already look.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MinIO object store → medallion fast-path decision | A JSON object read from S3 decides whether a correctness gate executes |
| medallion runtime configuration → receipt identity | A rollout-state change must invalidate a certificate produced under the previous state |
| `SHADOW_BUSINESS_COLUMNS` / `compare_business_state` → receipt identity | A change to what the comparison checks must invalidate certificates produced by the old contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-21 | Elevation of privilege | a forged or stale certificate causing validation to be skipped | mitigate | **The primary security property of this plan.** A skipped comparison is a skipped correctness gate, so the receipt must match on all four identities and carry `result == "equal"`; any failure to establish that runs the full comparison |
| T-04-22 | Spoofing | `None` snapshot ids certifying an empty or unknown lake | mitigate | Both current ids must be non-`None` before the receipt is read or written at all; a `None` never matches |
| T-04-23 | Tampering | a stale projection version certifying a changed contract | mitigate | The projection identity is a `hashlib.sha256` digest of the business and excluded column tuples plus a hand-bumped `SHADOW_CONTRACT_VERSION`, so the most likely real change invalidates certificates automatically; a test pins that |
| T-04-24 | Input validation | malformed or wrong-version receipt JSON | mitigate | Validated before use; anything unusable is treated as absent, which means run the comparison. Never trusted partially |
| T-04-25 | Information disclosure | receipt-failure logging | mitigate | Receipt failures log identifiers and counts only, never row payloads; the existing mismatch dump is not widened |
| T-04-26 | Configuration | a new env var undeclared in compose or `.env.example` | mitigate | `MEDALLION_SHADOW_RECEIPT_PATH` is declared in all three places, and the pre-existing `MEDALLION_COMPLETION_LEDGER_PREFIX` gap is closed at the same time; `docker compose ... config --quiet` gates it |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No package is installed in this plan |
</threat_model>
