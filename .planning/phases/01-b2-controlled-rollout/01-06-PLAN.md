<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Medallion -> PostgreSQL metrics | Best-effort application metrics become durable evidence. |
| Medallion/exporters -> Prometheus | Runtime signals are scraped through a monitoring boundary. |
| Telemetry rows -> summary calculations | Raw observations become amplification and validity claims. |
| Telemetry gate -> decision record | Validity controls whether deferred work may be opened. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | Telemetry window | mitigate | Preserve raw SQL rows, timestamps, runtime config, and Prometheus responses before calculating ratios. |
| T-01-02 | Spoofing | O1 health evidence | mitigate | Require both PostgreSQL rows and Prometheus query responses with source/status labels. |
| T-01-03 | Denial of Service | Metrics validity | mitigate | Treat missing/invalid telemetry as a failed gate and rollback Gold safely. |
| T-01-04 | Information Disclosure | Evidence artifacts | accept | Artifacts contain operational counters and paths only; do not include credentials. |
| T-01-SC | Tampering | Package installation | accept | No package installation is planned; unexpected installation blocks the observation window. |
</threat_model>
