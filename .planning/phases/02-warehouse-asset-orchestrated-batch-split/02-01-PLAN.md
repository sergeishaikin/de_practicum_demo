<threat_model>
## Trust boundaries and mitigations

| ID | Risk | Mitigation |
|---|---|---|
| T-02-01 | A task emits a scheduling event before data is ready | Only the terminal publisher declares core outlets; retries are zero; readiness and all predecessors must succeed. |
| T-02-02 | Event metadata or URI leaks secrets | Fixed repository Asset URIs and integer row counts only; no credentials/run IDs in `extra`. |
| T-02-03 | A stale or unrelated event is certified | Verify expected URI, producer DAG, source run, automatic run type, exact audit pair, and one unambiguous candidate. |
| T-02-04 | Existing PostgreSQL volumes miss the new column | Idempotent migration runs from existing bootstrap and is tested twice while preserving historical NULL rows. |
| T-02-05 | SQL injection through run IDs | Parameterize all DWH audit and verifier values; metadata SQL uses generated IDs through safe parameters/quoting. |
| T-02-06 | Runtime repair destroys state | Recreate only the inspected stateless Spark worker; never delete named volumes or use reset/prune/down -v. |
</threat_model>
