# S1.2 — legacy outbox handoff reconciliation

Status: **S1.2A.1 verified; cleanup not approved**.

S1.1 migrated the authoritative Bronze and reconciled Silver through the
accepted B2 projection, but it did not remove pre-M1 Bronze outbox manifests.
Those manifests are work-control markers, not Bronze data. A stale marker can
therefore make a restarted B2 processor rediscover already-migrated physical
files without implying data corruption.

## S1.2A dry-run contract

`iceberg/medallion/legacy_outbox_reconciliation.py` contains the read-only
classifier and the narrowly scoped S1.2A.1 recovery seam. The classifier does
not delete manifests, write Iceberg tables, or write parquet files. The
recovery seam may commit completed progress for one proven no-op, but leaves
that manifest in place. Every manifest is classified as one of:

- `SAFE_STALE` — historical work fully subsumed by migrated Bronze/Silver;
- `LIVE_POST_MIGRATION` — legitimate work after the S1.1 boundary;
- `IN_FLIGHT_BLOCKED` — work still reserved by active medallion progress;
- `BLOCKED` — any other failed-closed proof condition.

The classifier checks:

- the manifest load-id is present in Bronze snapshot history;
- its append snapshot predates the S1.1 migration boundary;
- its physical rows are consumed exactly once from authoritative Bronze;
- its order IDs resolve to the current authoritative B2 state in Silver; and
- no active/in-flight progress entry references the manifest or its files.

The accepted legacy singleton rule is used only to normalize a NULL physical
version to `business_version=1` for comparison. The classifier never derives
business order from Kafka offset, partition, event time, or file order.

The cleanup digest covers only the exact manifest object paths classified as
`SAFE_STALE`. Cleanup is a separate operation requiring an explicit approval;
this phase intentionally contains no apply/delete flag.

## S1.2A.1 recovery result

The single blocked item was investigated against durable evidence. Its outbox
manifest and `progress.work` entry existed, no `completed` entry existed, and
no Silver snapshot carried `silver-work-id=00833e23bddc4c428692642b37891afa`.
The 20 raw rows were all represented in authoritative Bronze after the
documented singleton legacy normalization, and B2 resolution against current
Silver returned zero advancing rows. This proves a crash-before-Silver-commit
whose logical result was already present after S1.1 migration.

Recovery used the M3 progress commit helper with `delete_outbox=False`:

```text
progress.work -> progress.completed
Silver mutation: none
manifest deletion: false
```

The post-recovery receipt is
`artifacts/s1.2a1-post-recovery.json`. Its final disposition is:

| Disposition | Count |
| --- | ---: |
| `SAFE_STALE` | 140 |
| `LIVE_POST_MIGRATION` | 255 |
| `IN_FLIGHT_BLOCKED` | 0 |
| other `BLOCKED` | 0 |

The SAFE_STALE set legitimately changed because the recovered manifest is now
completed progress and remains present for later cleanup. The new cleanup
digest is
`231cefaadc2a0ceb35dfc6a7dacd6f2f75512650d6e1345ead681c84171939bf`.
This differs from the frozen pre-recovery digest, so the old cleanup approval
cannot be reused. No cleanup was executed.
